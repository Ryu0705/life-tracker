## 0. 相手の土俵（Gymwork 録画から読めたもの）

- ホーム（sheet_09）: 上部に週カレンダー（月〜日）、食事 kcal・筋肉の回復カード、「実施したワークアウト」= **セッション単位のカード**（フリーワークアウト / 完了 / 2分・1440kg / 部位・種目）、下部に**「フリーワークアウト」「AIワークアウト」の開始ボタン**。タブ: 運動 / 分析 / プログラム / ランキング / プロフィール
- ワークアウト終了時（sheet_08）: 「完了」→「新しいルーティンとして保存しますか？」→ 動画広告 → **シェアカード**（日付・運動完了日数・ボリューム・カロリー・e1RM）→ 分析画面「9月5週目 / 週間平均ボリューム / 曜日バー / 総ボリューム」
- 画面上部に常時「運動時間 N分」「0kg 0kcal 0セット」のセッション計測バー
- オンボーディング（sheet_01）: 体型選択・食事プラン・HealthKit 許可・課金トライアル

→ Gymwork の非記録画面は **「セッション（開始→完了）」を単位として組み立てられている**。ここが LT の本人決定と真正面からぶつかる。

## 2. 分類

### 2-1. 不変条件（Gymwork 化しても絶対に守る）

| ID | 不変条件 | 元 |
|---|---|---|
| INV-1 | **記録の前後に開始/終了/完了/保存の操作を要求しない**。「ワークアウト開始」「完了」「保存しますか？」を記録の必須経路に置かない（任意のボタンとしても、押さないと何かが欠ける設計は不可） | T1【本人】 |
| INV-2 | **まとまり（セッション）はアプリが記録から自動で作る**。ユーザーがセッションを作る・閉じる・名付ける操作を前提にしない。1日=1セッション（JST 暦日）を崩さない | T1, T2 |
| INV-3 | **前回値プリフィル＋✓だけで記録できる経路を最短経路として残す**（起動→トレーニングタブ→種目追加→✓）。この経路のタップ数を増やさない | T3, P8 |
| INV-4 | **推移は全指標切替・ウォームアップ除外・自分比較のみ**。指標を減らす／ウォームアップを混ぜる／他者比較を入れる、は不可 | T4, T5, T9 |
| INV-5 | **導出値のためにテーブルを増やさない**（PR・週ボリューム・ストリーク・部位バランスは workout_set から導出） | T6 |
| INV-6 | **Grit 境界 A'**: トレーニング以外の習慣化の見せ方（汎用ストリーク・リング・ヒートマップ・習慣チェック）を LT に作らない。トレーニングの「連続週数」は Round 4 の対象内だが、**トレーニング進捗の文脈に閉じる** | P3【本人】 |
| INV-7 | **v2 の中心（今日タブ＝時刻ベースの予実）を従属させない**。トレーニングをアプリのホームに昇格させて今日タブを奥に押しやる／今日タブにトレーニング専用 UI を持ち込んで予実ビューを侵食する、は不可 | P1, P2【本人】 |
| INV-8 | **データは自前 DB に構造化で貯め、workout_session は独立アグリゲート（actual_task_id nullable）**。Round 5 の合流経路を塞がない | P4, P5 |
| INV-9 | **個人ツール**: 課金・広告・オンボーディング・シェアカード・ランキング・SNS・kg/lbs 切替・多言語は入れない | P6【本人】 |
| INV-10 | **本人指定の刻み（1.25/5, 2/4）と休憩 3:00 等、本人が決めた値を汎用既定値で上書きしない** | T10【本人】 |

### 2-2. 守りたいが条件付きで変えてよい

| ID | 項目 | 変えてよい条件 |
|---|---|---|
| C-1 | TabView 2タブ構成（今日/トレーニング）【AI既定】 | タブを増やす場合: ①今日タブが先頭・既定のまま ②トレーニングの記録面が1タップで開ける ③同じ情報を2タブで二重表示しない（C-7/C-3）。「分析」タブ新設は可だが、種目詳細の推移と重複しないこと |
| C-2 | ルーティン UI なし（Round 4 送り） | Round 4 の前倒しとして入れるのは可。ただし ①ルーティンは「種目カードを一括で並べるショートカット」であり**開始ボタンではない** ②pattern/task_template に相乗りしない（判断C） ③ルーティン未使用でも記録経路が完全に成立 ④「完了時に保存しますか？」ダイアログ方式は不可（INV-1）→ 保存は任意の場所から能動的に |
| C-3 | 過去セッション/過去日の履歴表示（Round 4 送り） | 追加は歓迎（C-4 CRUD 対称性の穴埋め）。**単位は「日」**で見せる。セッションカード化するなら 1日=1カード（Gymwork の「フリーワークアウト」名・運動時間は出さない or 最初〜最後のセット時刻から導出） |
| C-4 | 週カレンダー無し | 入れてよい条件: トレーニングタブ内で「どの日にやったか」を示す**トレーニング文脈に閉じたもの**。今日タブの日付ナビ（Round 7 過去日表示）と二重化しない設計の説明があること。Grit 的習慣ヒートマップへ拡張しない |
| C-5 | カード並び固定・下書きはメモリのみ【AI既定】 | 並び替え（ドラッグ）は可。下書き永続化は DB に「未完了セット」を入れる形なら PR/推移から除外が保証されること |
| C-6 | セットの編集不可（削除→再記録） | 編集追加は歓迎（Round 4 予定）。記録済み行の編集で PR 判定・1RM トーストが二重発火しないこと |
| C-7 | 部位別バランス・連続週数・週ボリュームが未実装 | Round 4 スコープ内なので Gymwork の「週間平均ボリューム」「曜日バー」型で入れてよい。導出のみ（INV-5）、週目標は UserDefaults |
| C-8 | 進捗導線が「トレーニングタブ下部の種目リスト→種目詳細」 | 分析画面の新設で置き換えてよい。ただし種目ごとの推移・履歴・メモに**2タップ以内**で届くこと |

## 4. Gymwork 化提案の評価チェックリスト（Yes で合格）

1. 起動からその日最初のセット ✓ までのタップ数は、現行以下か？（数値で比較）
2. 記録に「開始」「完了」「保存」「セッション選択」のいずれの操作も必須でないか？
3. セッション（まとまり）は記録から自動生成され、1日=1セッション（JST 暦日）が保たれるか？
4. 種目を追加したとき、前回値で埋まった行が出て ✓ だけで記録できる経路が残っているか？
5. 推移は全指標切替・ウォームアップ除外・自分比較のみのままか？
