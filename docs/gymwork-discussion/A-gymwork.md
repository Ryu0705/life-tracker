## 0. 前提として守るもの（この提案全体の制約）

### 本人決定で不採用（提案しない／代替のみ）
- ワークアウト開始・終了ボタン（儀式）→ LT は「その日最初のセットで裏で session 自動作成」を維持
- 課金・広告・ランキング・SNS（プロフィール/SNSログイン含む）・オンボーディング・AI ワークアウト/AI コーチング・kg/lbs 切替

### LT の良いところ（潰さない）
| # | LT の良いところ | 寄せるときの注意 |
|---|---|---|
| L1 | 開始/終了なし。開いて✓を押すだけで記録になる | 「完了」「保存しますか？」系のモーダルを一切足さない。サマリーは常時表示で代替 |
| L2 | 種目を足すと前回の値で行が埋まる（Gymwork の「読み込む」より手数が少ない） | ルーティン系の提案はこの仕組みの上に載せる |
| L3 | 今日の種目カードが 1 画面に縦に並ぶ（種目ごとに画面を掘らない） | ホームと記録画面を分けない（Gymwork はホーム→ワークアウト画面の 2 層） |
| L4 | 推移グラフが指標切替（最高重量/推定1RM/総ボリューム、自重=回数、時間、距離）で種目の metric_kind に追従 | 分析を足しても種目詳細の指標切替は残す |
| L5 | metric_kind 4 種（重量×回・回のみ・時間・時間＋距離）に列が追従 | 週ボリュームなど「kg 前提」の集計は weight_reps 以外の扱いを決めておく |
| L6 | 習慣化（頻度・連続日数）は Grit の担当、LT は時刻に紐づくもの（案 A'） | Gymwork の「運動完了日数」「🔥連続」系は LT に入れない（Grit と二重管理になる） |
| L7 | データは自前 Supabase（AI が後から分析できる） | 画像保存やシェアは「データの外出し」ではなく補助に留める |

## 4. 優先度つき提案（テキストワイヤー付き）

### 情報設計の骨格（提案全体の前提）
トレーニングタブを「日付を持つ 1 画面」にする。上から **週カレンダー帯 → 今日の合計ヘッダー → 部位の回復（任意） → 種目カード群 → ＋追加 FAB**。分析はタブ右上ボタン（または帯の週ラベルタップ）から push。**タブは増やさない**（「今日」「トレーニング」の 2 タブ＝ジムで 1 タップの原則を維持）。

```
┌ トレーニング                        [📊分析] ┐
│  9月 5週目            ‹  ›                    │
│  月  火  水  木  金  土  日                    │
│  28  29 (30)  1   2   3   4                   │
│   ・      ・                ← 記録がある日に点 │
├───────────────────────────────────────────────┤
│  1,440kg    3セット    2種目    28分           │ ← 今日の合計（✓で増える）
├───────────────────────────────────────────────┤
│ 前回の組み合わせ: [胸・三頭 9/27] [背中 9/25] ›│ ← 読み込みチップ（提案 4）
├───────────────────────────────────────────────┤
│ ■ ベンチプレス           e1RM 69kg ↑1.5  ⋮   │
│   今日 1,105kg ・ 前回比 +120kg               │
│   セット | 前回 | kg | 回 | ✓                 │
│   ...                                          │
│   [＋ セット]                                  │
│ ■ ダンベルベンチ ...                           │
│                                                │
│ 今日のメモ: 肩の違和感なし、ベンチ混んでた      │
│                                   (＋ 追加)  ← FAB │
└───────────────────────────────────────────────┘
```

### 高

**P1. 今日の合計ヘッダー（G9 の代替・開始ボタンなし）** — 高
- 表示: 総ボリューム（weight_reps のみ、ウォームアップ除外）/ 本番セット数 / 種目数 / 経過時間
- 経過時間は「今日の最初のセット completed_at → 最新セット completed_at（または now）」。開始操作なしで出せる（L1 を守る）。0〜1 セット時は非表示
- kcal と「💪連続」は出さない（精度・Grit 境界）
- 効き目: ✓ のたびに合計が増える＝Gymwork の報酬感を儀式なしで得る
- ワイヤー: 上図 2 段目。スクロールで上部に固定（pinned header）
- 実装: store.sets から pure function（WorkoutLogic.daySummary）→ テスト可能。DB 変更なし

**P2. 週カレンダー帯＋日付切替（G1 の寄せ／Round 4「過去セッションの履歴表示」を前倒し）** — 高
- 帯の日付タップでその日のワークアウトを**読み取り専用**で表示（カード＋セット列＋その日の合計＋メモ）。今日に戻るのは「今日」ボタン or 今日の日付タップ
- 記録がある日に点。‹ › で週送り。連続日数などは出さない（点は「どの日にやったか」の事実のみ）
- 過去日への追記・編集は今回スコープ外（C-4 CRUD 対称性は Round 4 のまま）→ 過去日ではセット行を読み取り表示、FAB を隠す
- ワイヤー（過去日）:
```
│  月  火  水  木  金  土  日                    │
│  28 (29) 30   1   2   3   4                   │
├───────────────────────────────────────────────┤
│ 9/29(火)  1,105kg  3セット  1種目  12分  [今日へ]│
│ ■ ベンチプレス   e1RM 69kg                     │
│   1  60kg × 5                                  │
│   2  57.5kg × 7                                │
│   3  57.5kg × 7                                │
│ メモ: —                                        │
```
- 実装: 日付範囲で全種目のセットを取る API（fetchSets(from:to:)）を WorkoutDataSource に追加。モック・Supabase 両実装

**P3. 種目カード見出しの強化（G11・⋮・⇄）** — 高
- サブ行: `今日 1,105kg ・ e1RM 69kg（前回 67.5）`。Gymwork の「交互表示」は見逃すので LT は**並べて常時表示**（改善寄せ）
- ⋮ メニュー: 推移を見る / 種目メモを編集 / 種目を入れ替え（未記録時のみ）/ 今日から外す（未記録時のみ）
- 見出しの種目名タップ＝推移（現状維持 L4）。📈 アイコンは ⋮ に吸収してもよい
```
│ ■ ベンチプレス                           ⋮   │
│   今日 1,105kg ・ e1RM 69kg (前回 67.5)       │
│   ┌──────────────┐                          │
│   │ 推移を見る      │                          │
│   │ メモを編集      │                          │
│   │ 種目を入れ替え  │ ← 同部位の候補シート       │
│   │ 今日から外す    │                          │
│   └──────────────┘                          │
```

**P4. 「前回の組み合わせを読み込む」（G5/G6/G21 の代替・ルーティン保存ダイアログなし）** — 高
- 過去の日（直近 5 日分など）の「その日の種目セット」をチップで出す。ラベルは部位の上位 2 つ＋日付（例「胸・三頭 9/27」）。タップ → G6 相当の確認シート（種目・セット数・重量の要約）→［読み込む］で今日のカードに一括追加（行は L2 の仕組みで前回値埋め）
- **保存操作が不要**: 毎回の記録そのものがルーティンになる（Gymwork の「完了時に保存しますか？」を丸ごと不要にする）
- 名前付きで固定したいメニューが出てきたら、Round 4 で既存の Routine テーブルに「この日の組み合わせを名前を付けて保存」を足す（⋮ から、ダイアログを自動で出さない）
- 今日すでに種目がある場合、チップは折りたたむ（「前回の組み合わせ ›」の 1 行）
```
│ 前回の組み合わせ                               │
│ [胸・三頭 9/27] [背中・二頭 9/25] [脚 9/23]    │
│      ↓ タップ                                  │
│ ┌ 9/27(土) 胸・三頭 ─────────────┐           │
│ │ ベンチプレス   3セット 60kg×5〜  │           │
│ │ ダンベルベンチ 3セット 16kg×15   │           │
│ │ ケーブル PD    3セット 25kg×12   │           │
│ │          [読み込む（3種目）]      │           │
│ └────────────────────────────┘           │
```

**P5. 週分析画面（G24〜G25）** — 高
- 入口: トレーニングタブ右上［📊］または週帯の週ラベルタップ → push
- 内容: 週ナビ / 週の総ボリューム（大数字）＋前週比 / 曜日棒グラフ（部位で積み上げ色分け）/ 部位別の本番セット数（週）一覧 / その週に自己ベストが出た種目
- 部位別セット数は「週あたり 10〜20 セット」等の一般的な目安と比べやすい（Gymwork はボリュームのみ。LT はセット数を足して上位互換にする）
- Gymwork の「週間平均ボリューム」は定義が曖昧（1 日目で総量と同値）なので採らず、**総量と前週比**にする
- duration / reps_only 種目はボリュームに含めず、セット数にだけ数える（L5）
```
┌ ‹ 分析                                        ┐
│  9月 5週目  9/28(月)〜10/4(日)       ‹  ›     │
│  総ボリューム 2,545kg   前週比 +12%           │
│  ▇                                            │
│  ▇   ▇                                         │
│  月  火  水  木  金  土  日   ■胸 ■背中 ■脚   │
│  ─────────────────                            │
│  部位別セット数（本番）                        │
│   胸     6  ███████                           │
│   三頭   3  ███                                │
│   背中   0                                     │
│  ─────────────────                            │
│  今週の自己ベスト: ベンチプレス e1RM 69kg      │
└───────────────────────────────────────────────┘
```
- 実装: P2 と同じ日付範囲 API を使う。集計は pure function

### 中

**P6. メモのインライン編集（G10・G12）** — 中
- 種目カード最下部に「メモ…」行（exercise.note、次回も表示される＝シート高さ・グリップ位置など）。今日のメモはカード群の最後（workout_session.note。セッションが無ければ最初の入力時に裏で作成＝L1 を守る）
- 既存カラムを使うので DB 変更なし（exercise.note の更新 API は追加要）

**P7. 部位の回復一覧（G3・G26 の代替。人体図は作らない）** — 中
- 部位ごとの「最後に本番セットをやった日からの経過日数」をチップで並べる。帯の直下に 1 行、今日の種目が入ったら折りたたみ
- 「回復度 %」のような根拠の弱い推定は出さない。事実（経過日数）だけ
```
│ 前回から: 胸 今日 ・ 背中 4日 ・ 脚 6日 ・ 肩 3日 │
```
- 効き目: 「今日どこやるか」の判断が開いた瞬間にできる。P4 のチップと並べると「脚が 6 日空いてる → 脚 9/23 を読み込む」が 2 タップ

**P8. 追加 FAB と一括✓（G19・G13）** — 中
- ［種目を追加］を List 内ボタン → 右下の FAB（休憩バー表示中はその上に逃がす）。スクロール位置に関係なく親指で押せる
- カードに「残りを全部✓」は入れない（誤タップで一括記録のリスクが大きい）。代わりに既存の「残りのセットに適用」を維持
- 目標回数の表示（G14 の 10-12）は Routine.target_reps が入るようになってから（P4 を名前付きルーティンに発展させた後）

**P9. 時間種目のストップウォッチ（G16 を LT 流に限定）** — 中
- metric_kind = duration / duration_distance の行を編集中だけ、シートに［▶ 計測］を出し、止めた値を時間欄に入れる（プランク等）
- 重量種目のセット中ストップウォッチは入れない（入力の手数が増える・開始の儀式に近い）

### 低

**P10. 今日のまとめ画像（G23 の個人版）** — 低
- 日付ビュー（P2）の合計行 ⋮ →「画像として保存」。SNS 連携・背景切替・ストーリー共有はしない（ShareLink の標準シートのみ）
- 中身: 日付・合計・種目×セット列・e1RM。人体図・完了日数・kcal は入れない

**P11. 1RM 計算機／重量×回数の換算（G29）** — 低
- 種目詳細の推移グラフ下に「e1RM 69kg → 8回なら 55kg、5回なら 60kg」の換算表を自動表示（計算機画面は作らない）。推定1RM は既存の Epley を使う

**P12. 休憩の既定値変更（G15「推奨 3:00 >」）** — 低
- 休憩バーの「3:00 ›」タップで 1:30/2:00/3:00/4:00 を選ぶ。種目ごとに覚えるかは本人確認

**P13. 体重・体組成（G27）** — 低
- LT で入力は作らない（入力画面が増える）。やるなら HealthKit の体重を読み取って週分析に 1 行並べる。範囲外なら保留

**P14. 器具フィルタ・種目自作（G20）** — 低
- 種目マスタ 159 件。部位チップ＋検索で足りている間は不要。自作は MCP 経由の登録で代替できている

### 不採用（明記）
- 連続日数・運動完了日数バッジ（Grit と二重管理＝L6）、kcal 推定、完了時のルーティン保存ダイアログ・祝福画面（儀式）、ワークアウト最小化バー（開始が無いので不要）、ウォームアップ/クールダウンストレッチ、プログラム・ランキング・プロフィール・SNS・AI・課金・広告、kg/lbs

## 5. 実装順の目安（手戻り観点）
1. データ層: `fetchSets(from:to:)`（全種目・日付範囲）＋ pure function（daySummary / weekSummary / lastTrainedByMuscle / pastCombinations）＋テスト — P1/P2/P4/P5/P7 の共通土台

3. P4 読み込み → P7 回復一覧（同じ帯領域の設計なので続けて）
4. P5 分析画面
5. P6/P8/P9、以降低優先

| # | 論点 | 既定値（推進派） | 代替 |
|---|---|---|---|
