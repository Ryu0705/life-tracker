## 1. 結論（先に要約）

- プログラムを**使う**導線（チップ → 確認 → 読み込む）はよくできている。一方、**保存する**導線は画面のどこにも見えていない。保存の入口は、ラベルの無い左上のアイコン1つの奥にしかない（A-1, A-2）
- 【推測】本人の「どうやって保存するの？」という質問の原因は、次の3つが重なったことだと考える。検証はしていない
  - (1) 保存の入口が「今日の記録を見ている画面」に無い
  - (2) 左上のアイコンにラベルが無く、意味が読めない
  - (3) Gymwork の「今日やった内容をルーティンとして保存」という習慣と、LT の「管理画面で新規作成」という設計がずれている
- 同じプログラムでも、置かれた場所によってタップしたときの動きが違う（チップは読み込み、一覧の行は編集）。また、見た目が同じチップに、絞り込みと画面移動という別の動きが混ざっている（A-3, A-4）

### A-1【高】今日の画面に「プログラムとして保存」の入口が無い

- **画面/ファイル**: トレーニング（今日・種目あり）`WorkoutView.swift:200-210`、`ProgramViews.swift:137-145`
- **問題**
  - 【事実】本画面の「プログラム」欄は、今日が空のときだけ出る（`if store.todayExerciseIds.isEmpty && programStore.isLoaded`、`WorkoutView.swift:201`）。種目が1つでも入ると、本画面からプログラムに関係する文字はすべて消える（u1）
  - 【事実】「今日の種目から作成（N種目）」はプログラム一覧（push 先）の先頭にしかない（`ProgramViews.swift:137-145`、p4）。たどり着くにはラベルの無い左上のアイコンを押す必要がある
  - 【事実】Gymwork では、完了すると「新しいルーティンとして保存しますか？」と聞かれる。そのダイアログには「今保存しなくても、完了した運動記録の『その他』から新しいルーティンとして保存できます」と書かれている（`rec/sheet_08.png` 下段）。つまり Gymwork は**記録の現場（今日の記録の ⋮）から保存できる**
  - 【推測】本人の頭の中にあるのは「今日やったものを保存する」という流れだと考える。LT の「管理画面を開いて新規作成する」は、その流れと入口の場所がずれている。これが「どうやって保存するの？」の主な原因だという仮説を置く（検証していない）
- **根拠**: u1s.png（種目ありの本画面にプログラム関連の表示が無い）、p4s.png、`rec/sheet_08.png`、設計 SSOT「変更 1」P-4（「終了時の保存ダイアログは作らない」）
- **改善案**（儀式を足さない形。ダイアログは出さない）
  - 現状: 種目ありの本画面 → 左上アイコン → 一覧の先頭行「今日の種目から作成」→ 名前 → 保存（入口を知らないと見つからない）
  - 変更後（案1・推奨）: 合計バー（`DaySummaryBar`）の右端、または種目リスト最後の［種目を追加］の下に、目立たない1行「今日の種目をプログラムとして保存」を置く。押すと既存の `ProgramEditView`（今日の種目が入った状態）を直接シートで開く。表示条件は今日の種目が1つ以上あること。操作が必須にはならないので INV-1 には触れない
  - 変更後（案2）: 上の1行を［種目を追加］セクションの footer にテキストリンクとして置く。縦の場所をいちばん取らない
  - 他の選択肢と採らない理由: Gymwork 型の完了ダイアログは、完了操作が無いので置く場所がなく、本人方針（INV-1）にも反する
- **横展開確認**: 過去日（`PastDayView`）にも「この日の種目をプログラムにする」入口は無い。過去の良かった日から作りたいという要求は同じ形なので、案1の後に検討する（低）

- **改善案**
  - 現状: 左上にアイコンだけ［≣］、右上にアイコンだけ［📊］

### A-3【高】同じプログラムでも、タップの結果が「読み込み」と「編集」に分かれている

- **画面/ファイル**: `ProgramViews.swift:147-162`（一覧の行 → 編集）、`WorkoutView.swift:206` / `ExercisePickerView.swift:75`（チップ → 読み込み）
- **問題**
  - 【事実】チップ（本画面・種目追加シート）を押すと確認シートが開き、そこから読み込める。一覧の行を押すと編集シートが開く。一覧から読み込む方法は無い（p4 → p9）
  - 【事実】Gymwork のマイルーティン一覧では、行を押すと「前回のワークアウト記録」シートが開き、［読み込む］で使える。編集は ⋮ から行う（`docs/gymwork-discussion/A-gymwork.md` G5/G6。録画フレームでの一次確認はしておらず、A 担当の棚卸しに頼っている）
  - 【推測】一覧の中身がチップと同じ並びなので、利用者は一覧を「プログラムを選んで使う画面」と受け取りやすい。行を押すと編集が開き、値を変えるつもりが無いのに編集画面に入ってしまう
- **根拠**: p4s.png → p9s.png、`ProgramViews.swift:148`
- **改善案**
  - 現状: 行タップ = 編集 / スワイプ = 削除 / 読み込みは不可
  - 変更後（推奨）: 行タップで確認シート（`ProgramLoadSheet`）を開いて読み込めるようにする。編集は、行の右端の［編集］ボタン（`info.circle` 等）、長押しの `contextMenu`（編集・削除）、または確認シートのツールバーの［編集］に移す。こうすると、プログラムという同じものに対して、どこから触っても「押す = 使う」にそろう
  - 案2: 一覧を管理専用のままにするなら、ナビタイトルを「プログラムの管理」にし、行に `chevron` と「編集」の文字を添えて、押すと何が起きるかを見せる
- **横展開確認（CRUD マトリクス）**

| 操作 | 本画面チップ | 種目追加シートのチップ | 一覧 | 編集シート |
|---|---|---|---|---|
| Create | 空＆0件時のみ「プログラムを作る」 | なし | ＋ / 今日の種目から作成 | — |
| Read（中身） | 確認シート | 確認シート | 行の副題（種目名） | ○ |
| Load（使う） | ○ | ○ | **×** | × |
| Update | × | × | 行タップ | ○（名前・種目・並び） |
| Delete | × | × | スワイプ | **×**（中から削除できない） |
| 並べ替え（プログラム同士） | × | × | **×** | — |

  Update と Delete が一覧でしかできないのは、管理画面としては成り立っている。欠けているのは「一覧から使う」と「プログラム同士の並べ替え」の2つ（後者は A-10）。

## 4. 良い点

1. **呼び出しの手数が少ない**: 空の日は「チップ → 読み込む → ✓」で、行は前回の値で埋まる（p1 → p2 → p3）。Gymwork の開始儀式を通らずに同じ結果が得られている
2. **確認シートの情報の優先順位が正しい**: 種目名の下に「前回 60×10 / 65×8 / 65×6」を出していて、読み込む前に今日の重量の見当が付く（p2, u3）。追加済みの種目は「追加済み」と出して押せなくしており、二重に追加されない（`ProgramViews.swift:87-112`）
3. **読み込むボタンに件数が出る**: 「読み込む（3種目）」で、外した結果がボタンに反映される。0件のときは押せない
4. **空状態の使い方**: プログラム欄を空状態そのものとして出し、種目が入ったら消す。そのため、記録中は種目カードの先頭行の位置が変わらない（受け入れ条件を守っている）
5. **プログラムの記録と今日の下書きを分けている**: `ProgramStore` を今日の store と別に持っており、一覧や編集を触っても今日の下書きが壊れない
6. **編集画面の構成**: 名前 → 種目（件数つき見出し）→ 種目を追加、の順で1画面に収まる。種目は選んだ順に番号が付き、その順で入る（q1 → q2）
7. **「今日の種目から作成（N種目）」**: 今日やったものを保存するという発想を形にしている（場所の問題は A-1）
8. **過去日を読み取り専用にしたこと**: 今日の下書きや休憩バーを壊さずに過去日を見られる
