## 作り直しの経緯

2026-04-25 v1 (Plan A) を廃止し v2 として作り直し決定。**初期構想 (朝の習慣化ツール) と現構想 (1 日サイクル設計) のズレが連続発生**し、設計変更のたびに影響範囲が膨張したため、ドメイン / データモデルから書き直す判断。

drift の真因は「初期構想の解像度不足」で、朝の習慣は朝単体では成立せず夜→朝の全結合循環を言語化できていれば防げた。詳細経緯・drift 真因診断は memory `project_life_tracker_v2_core.md` 参照。

v2 ではコアの解像度を上げてから実装に入る。スコープ判定基準 (後述) で新機能採否を機械的に判定する。

## v2 確定コア定義

> **Life Tracker v2 = 1 日サイクル (朝・昼・夜の全結合チェーン) を設計・記録・可視化する個人ツール**

### スコープ判定基準

**1 日サイクル (行動・身体状態) に直接影響する要素のみ扱う**

新機能追加時、必ず本基準に照らす。スケジュール / 健康への影響が薄ければ却下。

### 対象

- 習慣化 (デフォルトパターンとして内包)
- 1 日のスケジュール (予実分離)
- 健康記録 (睡眠 / 食事 / 運動 / 体調)
  - ※ 本スコープ基準は「何を扱うか」しか判定しない。**どの解像度で扱うか**は別途判断が要る (v16 のトレーニング詳細化はこの穴を通った例)
- **学習記録** (PMBOK 計画と統合可能)

### 習慣化の境界線 (2026-09-30 本人決定)

- **時刻に紐づくもの → Life Tracker**、**頻度・回数だけのもの → 既製アプリ Grit**。1 つの行動はどちらか一方でだけ管理する (二重チェックを作らない)
- 理由: 本人が Grit の習慣化部分の作り込みに惹かれた一方、1 日の予定の予実は「要る」。習慣化の見せ方 (ストリーク・ウィジェット・Watch) は既製品の完成度に追いつくコストが大きい
- 帰結: Life Tracker 側では「習慣化専用の見せ方」は作らない。習慣はデフォルトパターン内の予定として扱う範囲に留める
- 経緯: `~/life/.life/personal-dev/life-tracker/grit-comparison-2026-09-30.md`

### 除外

- 仕事のタスク (PC でやる、スマホ入力しない)
- 時刻に紐づかない習慣 (水を飲む・読書 N ページ等) — Grit で管理 (2026-09-30)

### 保留 (1 日サイクルへの影響が薄い)

- 家計・支出 (やりたくなる可能性あり、影響少)
- 気分・メンタル (Apple Watch で別途検討、健康への影響は限定的)

## 構造原則

### 原則 1: 1 日 = 全結合の影響グラフ

- フェーズ間は線形チェーンではなく全方向に影響
  - 朝の起床時刻 → 夜の就寝時刻 (飛び越し影響)
  - 昼の疲労度 → 夜の行動の質
- 時間帯 (朝 / 昼 / 夜) は **第一義的な区切りではない**。表示・分析時のフィルタ

### 原則 2: タスクと時刻枠を分離

- v1 (Plan A) では blocks 内に内容が直接埋まっており、タスク移動が扱えなかった
- v2 では「タスク (やりたいこと)」と「時刻枠」を別エンティティに
- タスクは時間帯間を移動可能 (朝できなければ昼 / 夜に振り替え)

### 原則 3: デフォルトパターン中心

- 「いつもの 1 日」をデフォルトパターンとして定義
- 当日の予定はパターン適用 + 当日修正で生成
- 当日の実績との予実差分で習慣化フィードバック

---

## v1 との断絶ポイント

- v1: blocks 内に予定・実績・内容が混在 → タスク移動・並列が扱えなかった
- v2: scheduled_task / actual_task 独立 + 並列許容 + サブ入力分離 + 種別正規化 → drift 耐性を構造で担保
- v2: 予実は DB レベル完全独立 (FK なし)、UI / Service 層で結合 (詳細は `domain-model.md` データモデル原則「予実紐付けなし」)

### Phase 1 で実装する範囲

- **DB**: `domain-model.md` の v16 DDL (詳細・サブ入力種別の SSOT は `domain-model.md` 側)
- **DayBuilder**: pure function、入力は `DayBuilderContext` 構造体に集約 (詳細は `domain-model.md`)
- **基本 UI** (Phase 1 範囲):
  - 当日表示画面 (Day 単位の scheduled / actual 並置、当日進行中タスクカード相当)
  - 過去日表示画面 (read-only、編集 UI なし)
  - pattern 切替シート / 「何もしない日」/「デフォルトに戻す」操作
  - tasks の追加 / 編集 / 削除 (F-A 3 択ダイアログ含む)
  - day_meta バッジ (ユーザー操作済み日のマーカー)
  - **テンプレ / パターン / カテゴリ管理 UI** (CRUD、exdate 編集含む。本人運用継続のため Phase 1 内で必要)
  - **トレーニング記録** (セッション / セット単位。種目マスタ・ルーティン管理を含む) — v16 で追加
  - **トレーニング進捗の可視化** (PR / 推定1RM / ボリューム推移 / 部位別バランス / 連続週数)
  - 未来日表示は **Phase 1 範囲外** (pattern 編集後の波及確認は当日 + 過去日のみで運用)
