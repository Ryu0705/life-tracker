## 0. 現状の確認（スクショとソースから。事実）
- 1 枚の List（`WeekAnalysisView.swift`）に、期間の単位が違う 3 つのかたまりが縦に並ぶ。

- 「種目ごとの推移」は全期間の一覧で、週ナビの影響を受けない。それなのに週ナビの下にあるため、週で絞られているように見える（ソースで確認: `progressExercises` は週に依存しない）。

## 3. 分割案

### 案A: 分析画面の上部に固定のセグメント「強さ｜継続｜中身」
```
┌ ‹ 分析 ──────────────────────┐
│ [ 強さ | 継続 | 中身 ]          │ ← スクロールしても上に残る（safeAreaInset）
├──────────────────────────────┤
│（強さ）                         │
│ ‹  直近30日 9/11〜10/10  ›       │ ← 期間ナビは 1 つだけ。List の先頭の行
│ ⚖ 70.1kg 10/7 · 今日の体重を入力 │
│ [人体図 前／後] 凡例             │
│ 部位ごとのレベル（9/11〜10/10）  │ ← 見出しに期間を書く（ナビが画面の外に出ても分かる）
│  胸  Novice 2.8 …               │
│ 種目ごとの推移（全期間）›一覧    │ ← 中身から移す（§4-2）
└──────────────────────────────┘
（継続）
│ 🔥 17日  ◔ 今週 2/4 · あと2回    │
│ 半年（草）  ← ナビなし・全体を見る │

│ [1 か月カレンダー]               │

│ ‹  今週 10/6〜10/12  ›           │ ← 週ナビ 1 つ

```
- 現状 → 採用後: 1 枚の縦スクロール（期間ナビが 2〜3 個） → 3 ページに分かれ、**1 ページに期間ナビは 1 個**（継続の半年はナビなし）。各ページは今の 1/3〜1/2 の長さ。種目一覧は強さへ、心肺は中身へ移す。継続の「1か月｜半年」の切替はやめて、2 つを縦に並べる。
- 長所: 3 つは同じ高さのもので、行き来は 1 タップ。行き来しても戻る操作がいらない。上のセグメントを見ればどのページにいるか分かる。期間ナビが 1 ページ 1 個になるので、どのナビがどの表を動かすかで迷わない。継続ページの中に切替がもう 1 段できる（セグメントの中にセグメント）のも避けられる。
- 短所: 3 つを同時には見られない（今は、スクロールすれば全部見られる）。セグメントの分だけ縦が約 44pt 減る。上部にセグメントを置く例は参考アプリでは確認できなかった。

### 案B: 分析トップをハブにして、3 画面へ push
```
┌ ‹ 分析 ──────────────────────┐
│ 強さ             直近30日  ›   │ ← カードごと push
│  [小さな人体図] 最も高い 胸 2.8  │

│  10,801kg 前週比 +23% · 28セット │
│ 種目ごとの推移            ›     │ ← C3 を守るため一覧の入口をハブに置く
└──────────────────────────────┘
  push → 各画面の上端に期間ナビを 1 つ（案A の各ページと同じ中身）
```
- 現状 → 採用後: 分析 = 1 枚 → 分析 = 4 行の目次＋3 つの詳細画面（Hevy の Statistics に近い形）。期間ナビは詳細画面にだけ置き、ハブは「直近」に固定する。
- 長所: ハブで 3 つの「今」がひと目で分かる。詳細画面は 1 つのことだけを扱うので、いちばんすっきりする。参考アプリの実例がある（Hevy・Apple フィットネス）。
- 短所: 強さ → 中身に移るには「戻る → 押す」の 2 操作が要る。ハブのカードと詳細の中身が重なる。継続の要約（🔥17日・今週 2/4）はトレーニングタブの 1 行（`ContinuityRow`）とも同じになり、同じ数字が 3 か所に出る。ハブに出す数字の選び方（何を「代表」にするか）という新しい設計が増える。種目の推移は 📊 → ハブの一覧 → 種目になり、C3 はぎりぎり守れる。

### 案C: 入口をトレーニングタブ側に分ける（分析は強さだけ）
```
トレーニングタブ
│ 🔥 17日 ◔ 今週 2/4 · あと2回  ›  │ ← タップ → 継続ページへ push（今の目標変更はページの中へ移す）
│ [週帯 月〜日]                     │ ← 週帯の右端「今週の中身 ›」→ その週の中身ページ（週ナビつき）
│ 今日のカード …                    │

```
- 現状 → 採用後: 分析 1 枚 → 3 つの入口がそれぞれの文脈の近くにある（連続の行 → 継続、週帯 → 週の中身、右上 → 強さ）。
- 長所: 見たい場所からそのまま入れる（今週の量は週帯から、連続は連続の行から）。分析画面は強さだけになるので、いちばん短くなる。
- 短所: 「分析」の意味が強さだけに狭まる。3 つを横に見比べる場所がなくなる。連続の行のタップは今は「目標の変更」（`continuity-design.md` の表示場所の行）なので、この動きを変えることになる。トレーニングタブを「今日の記録面」にするという J6 の考え方に、入口が 2 つ増える。週帯は過去の日を見る操作（R-2）に使っているので、役割が重なる。

### 参考（分割しない場合）: 1 枚のまま見出しで区切り、期間を揃える
- 3 つの期間を「30 日」に揃えて、ナビを先頭の 1 つにまとめる。週の中身が 30 日（4 週強）になり、曜日×部位の棒が読めなくなる。本人の言う「分けて表示」に答えていないので、案としては挙げない。

## 4. 期間ナビの数・置き場所・共有

### 4-1 ページごとのナビ（案A・B 共通）
| ページ | ナビ | 置き場所 | 単位 |
|---|---|---|---|
| 強さ | 1 | ページ先頭の行（`PeriodNavigator`）。期間に関係する節の見出しに日付範囲を書く | 30 日（今のまま。上限なし） |
| 継続 | 1（1 か月だけ） | 1 か月カレンダーの真上。連続・今週・半年はナビなし | 5 週（今のまま） |
| 中身 | 1 | ページ先頭の行 | 週（今のまま） |

- 推奨はナビを List の行に置く（スクロールすると画面の外に出る）。上のセグメントの下に固定する案もあるが、固定する部分が 2 段（約 100pt）になり、人体図が画面の 1 枚目に収まらなくなる。代わりに、期間で変わる節の見出しに日付範囲を書いておけば、ナビが見えなくても今どの期間かが分かる。
- 継続ページは「1か月｜半年」の切替をやめて縦に並べる。分けたあとのページには 2 つを並べる余裕があり、ページの中でもう一度切り替える（セグメントの中にセグメント）必要がなくなる。半年は全体を見るもの、1 か月はさかのぼるもの、と役割が分かれる。

### 4-2 ページをまたいで期間を共有するか → **共有しない**
- 単位が 30 日・5 週・1 週とばらばらで、共有するには換算の規則（「強さを 3 つ戻したら中身は何週目か」）が要る。規則を作っても、本人にとって予想しやすい動きにならない。
- 参考アプリでも、共有している例は確認できなかった（§1）。
- ページを切り替えても、各ページの戻した位置は保つ（分析画面の親が 3 つの offset を持つ）。分析画面から出たら直近に戻す（今の `weekStart = nil` と同じ考え方）。
- エッジケース: 中身で 8 月の週を見たまま強さに移ると、強さは直近 30 日のまま。ページごとにナビとその日付が見えているので、取り違えは起きにくいと考える。

### 4-3 中身を移す 2 か所（案A・B 共通の提案）
- **種目ごとの推移 → 強さページの末尾**（見出し「種目ごとの推移（全期間）」）。中身は e1RM・重さの推移なので強さに近い。週ナビの下から外れるので、今の「週で絞られているように見える」問題もなくなる。C3: 既定のページが強さなら 📊 → 種目 で 2 タップのまま。
- **心肺 → 中身ページ（その週の合計）**。心肺は時間・距離・回数の合計で、級が付かない。性質は「量」なので、総ボリュームと同じ週の単位にするほうが合う。これは 30 日の期間（AI 既定）を変えることになる。本人の決定は「別ブロック・合計だけ」で、期間は決めていない（`body-strength-and-heatmap-period.md` 項目 3）。

### 4-4 既定のページ
- 推奨: 開いたら毎回「強さ」から始める（今の並びの先頭で、本人の「人体図・上の方」に合う。C3 も 2 タップのまま）。
- 別案: 最後に見たページを覚える。中身を毎回見る使い方なら楽になるが、種目の推移まで 3 タップかかることがあり、C3 を守れない場合がある。

## 5. 推奨: 案A（上部の固定セグメント＋1 ページに期間ナビ 1 つ）
UX の観点での理由:
1. **3 つは対等で、行き来が多い。** トレーニングのあと「今週どれだけやったか（中身）」と「強くなったか（強さ）」は続けて見たくなる。案A は 1 タップで行き来でき、戻る操作がいらない。案B は毎回 戻る → 押す の 2 操作になる。
2. **期間ナビの迷いがなくなる。** 「見づらい」の原因の 1 つは、単位の違うナビが縦に重なっていることだと考えられる（スクショからの推測）。案A なら 1 ページに 1 個になり、ナビとそれが動かす表が同じページの中で対になる。
3. **同じ数字を何か所にも出さない。** 案B のハブは、トレーニングタブの連続の行・詳細画面と数字が重なり、3 か所に同じものが出る。案A は各ページに 1 回だけ出す。
4. **入口と記録面を守る。** 案C は J6（トレーニングタブは今日の記録面）と連続の行のタップ（目標の変更）を動かすことになる。案A は入口が「分析」1 つのままで、C2 を満たす。
5. C1 にも合う。セグメントが切り替えるのは中身の種類で、期間は各ページの ‹ › に任せる。役割が混ざらない。

案A の弱み（3 つを一度に見られない）は、今の 1 枚でもスクロールしないと見られなかったので、失うものは小さいと考える。参考アプリにこの形の実例がない点は、実物（または録画）で確かめたい（`feedback_ui_placement_check_real_apps`）。

## 6. 決裁用の整理（本人に渡す論点）
1. **要点**: 分析 1 枚 → 「強さ｜継続｜中身」の 3 ページ（案A）。期間ナビは 1 ページ 1 個、共有しない。あわせて 種目の推移 → 強さ、心肺 → 中身（週）、継続の 1か月｜半年 → 縦に並べる。
2. **エッジケース**: (a) 中身で古い週を見たまま強さに移ると期間が揃わない（共有しないので仕様どおり。ナビの表示で分かる） (b) 心肺を週にすると、30 日で 1 回だけのような少ない有酸素は、ほとんどの週で 0 になる (c) 継続を縦に並べると、半年の草と 1 か月で同じ日が 2 回出る。
3. **可逆性**: 画面の構成だけで、DB・計算は変えない。今の 3 つのセクション部品（`BodyStrengthSections`・`AnalysisContinuitySection`・週の部分）を並べ直すだけなので、1 枚に戻すのも並べ直しで済む。
4. **知識の在り処**: 決定は `docs/body-strength-and-heatmap-period.md` の構成の節と `gymwork-alignment-design.md` J6 の注記に書く。議論は `docs/analysis-tabs-discussion/`。
5. **網羅性**: 案B（ハブ → push）は 1 タップで行き来できず、数字が重なるので採らない。案C（入口を分ける）は記録面と既存のタップの動きを変えるので採らない。分割しない案は依頼に答えていないので採らない。下のタブに分ける案（Strong・Fitbod 型）は C2 に反するので挙げていない。
