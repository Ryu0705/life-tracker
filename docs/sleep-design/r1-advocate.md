## 0. 結論（推奨の一覧）

| # | 論点 | 推奨 |
|---|---|---|
| S1 | 記録をどの夜に属させるか | **起床した日（JST）で「10/2(金) の朝」と呼ぶ**。予定タブの回（就寝の日 D）とは「起床日 = D+1」で結ぶ |
| S2 | 昼寝 | 同じ表に「夜の睡眠／昼寝」の種類で持つ。夜の睡眠は 1 朝 1 件、昼寝は何件でも。種類は時刻から自動で選び、変えられる |

## 1. 実在の睡眠アプリから採る／採らない

確度の表記: **事実**＝公式の説明や広く知られた画面の形で確かなもの、**推測**＝記憶ベースで細部を確かめていないもの。実物の画面はこの Round では開いていない。

| アプリ | 実物の形 | 採る／採らない | 理由 |
|---|---|---|---|
| Apple ヘルスケア「睡眠」 | 日／週／月／6 か月の切り替え。週表示は夜ごとに就寝〜起床の**浮いた棒（範囲バー）**、平均睡眠時間を上に大きく（事実）。手入力は「データを追加」で開始・終了の日時を選ぶ（事実）。何回も掘る必要がある（推測: 6 タップ前後） | **範囲バーと期間切り替えを採る**。手入力の深さは採らない | 範囲バーは「何時間寝たか」と「何時に寝たか」を 1 つの絵で見せられる。手入力の深さは毎朝続かない側の見本 |
| ヘルスケア「睡眠スケジュール」／旧・時計アプリの「ベッドタイム」 | 円形のダイヤルで就寝と起床のつまみを回し、真ん中に睡眠時間（事実） | **今回は採らない**（候補として残す） | 1 回のドラッグで両端を動かせて気持ちよいが、SwiftUI に既製部品がなく 5 分刻みの精度も出しにくい。± ボタンで足りるか実機で見てから |
| AutoSleep | Apple Watch で自動計測。リング（睡眠時間・深い睡眠・質など）と 24 時間の時計型の表示（事実）。手で「寝る／起きた」を押す使い方もある（推測） | **リングの考え方だけ採る**（今週の記録数・平均を既存のリング部品で） | 自動計測は Watch 前提。本人が Watch で寝ているかは未確認 |
| Pillow | 寝る前に計測を始める。朝に気分を顔アイコンで付ける（推測を含む） | **朝の主観評価を 1 タップで付ける形を採る**。寝る前の開始は採らない | 寝る前の開始は「記録の前の儀式」（本人 NG・`feedback_input_ux`） |
| Sleep Cycle | 寝る前にアラームを設定して計測開始、朝に「目覚めの気分」と睡眠メモ（事実に近い。細部は推測） | **採らない**（気分の評価だけは Pillow と同じ扱い） | 寝る前の操作が前提 |
| Rise | 睡眠負債（必要睡眠との差の累計）とその日のエネルギーの波を出す（事実。必要睡眠は推定値） | **「予定との差」として採る**（推移画面に。1 画面目には出さない） | 必要睡眠の推定はできないので、本人が決めた予定（23:00〜8h）を基準にすれば新しい設定が要らない |
| Oura | 睡眠スコア・就寝時刻の規則性・推奨就寝時刻（事実） | **「就寝時刻のばらつき」だけ採る**。合成スコアは採らない | 合成スコアは中身がセンサー依存。手入力では作れない |

まとめ: 入力は「Gymwork 型（埋まっていて押すだけ）」、見せ方は「ヘルスケアの範囲バー＋Rise の予定との差」。寝る前に何かを押す系（Pillow・Sleep Cycle）はすべて採らない。

## 2. 論点ごとの案（現状 → 採用後の差分）

### S1 記録をどの夜に属させるか
- **現状（0007 実装）**: 睡眠の実績は actual_task に「予定の回の日 = 就寝の日 D」で付く。予定タブでは D の「今夜の睡眠」と D+1 の「前日から継続」の 2 行に同じ回が出る。0:30 に寝ても回の日は D
- **案 A（推奨）: 起床の日で呼ぶ**。睡眠タブでは「10/2(金) の朝」「10/2(金) 7時間30分」のように起床日を見出しにする。予定タブとは「回の日 D ↔ 起床日 D+1 の夜の睡眠」で結ぶ
  - 理由: 入れるのは朝。「今朝の睡眠」を入れるのに「昨日の夜」を選ばせると毎朝 1 回考えさせる。ヘルスケアも起床側の日で数える（`domain-model.md` の「HealthKit 同型＝終了ベース＋18:00 境界」と同じ向き。境界の値は推測を含む）
  - 予定タブの見え方は変わらない（D の今夜の行・D+1 の前日継続の行に同じ実績）
- 案 B: 就寝の日で呼ぶ（予定の回と同じ）。予定との結びは素直だが、0:30 就寝が「前日扱い」になるのは今と同じで、朝に「昨夜（10/1）」と書く必要がある
- 案 C: 時刻の重なりだけで結ぶ。夜をまたぐ 2 件・昼寝が混ざると予定の行に何を出すか決まらない
- エッジケース: 4:00 に寝て 12:00 に起きた → 起床日は同じなので問題なし。**18:00 に寝て 23:00 に起きた**（夕方に寝落ち）→ 起床日の夜の睡眠にすると、その夜の本番が「2 件目」になる。→ S2 の自動判定で昼寝扱いにする

### S2 昼寝
- **現状**: 昼寝は予定外の実績（actual_task）で記録する、という AI 既定（walkthrough の保留）
- **案（推奨）**: 睡眠の表に種類「夜の睡眠／昼寝」を持つ。夜の睡眠は**1 朝に 1 件**（DB の一意制約）、昼寝は何件でも。記録シートの種類は時刻から自動で選ぶ（起床が 12:00〜20:00 なら昼寝、推測で決めた境界。データ担当と詰める）が、押せば変えられる
  - 差分: 昼寝が「予定外の実績（用事などと同じ一覧）」から「睡眠タブ」へ移る。推移で「昼寝 計 40 分」を足せる
- 不採用: 昼寝を作らない（夕方の寝落ちが夜の睡眠に入り、平均が崩れる）／昼寝を別の表（同じ形の表が 2 つになる）

### S3 朝の入力の流れ
- **現状（0007 実装）**: 予定タブの前日継続の睡眠の行を押す → 予定の編集画面の下の「実績」欄 →「就寝・起床を記録する」→ 時刻 2 つ → スコア → 保存（最短 4 タップ、予定の編集画面を経由する）
- **案（推奨）: 睡眠タブの先頭に「今朝のカード」**
  - 就寝 = **予定の就寝時刻**、起床 = **開いた時刻（5 分単位に切り捨て）** で埋まっている。［記録する］で保存
  - 起床が「今」で埋まるのは、今朝の夜の睡眠が未入力で、かつ開いた時刻が予定の起床 −2h〜+5h の間（推測で置いた幅）のときだけ。それ以外（昼に思い出して入れる等）は予定の起床時刻で埋める
  - 最短 2 タップ（タブ・記録する）。これは Gymwork 型で本人が「正解形」とした「前回値で埋めて ✓ だけ」と同じ
- 就寝の既定をどうするか（サブ案）
  - a（推奨）予定の就寝（23:00）: 予定タブの「予定の時刻が入った状態から直す」と同じで説明が要らない
  - b 直近 7 夜の就寝の中央値: 毎日 0:30 に寝ている人は直す回数が減る。ただし「なぜこの時刻？」が見えない。記録が 7 件たまってから効く
  - → a で始め、実機で毎朝ずらしているなら b に切り替える（列も設定も要らない、表示の規則だけの差し替え）
- 不採用
  - 起動時に睡眠タブを自動で開く／朝に全画面のシートを出す: 段階 2 の C5 で本人が不採用にした「朝に専用シート（毎朝の必須入力＝儀式）」と同じ
  - 寝る前に「寝る」を押す（Pillow・Sleep Cycle 型）: 記録の前の儀式

### S4 時刻の直し方
- **現状**: DatePicker（ホイール）で時刻を選ぶ
- **案（推奨）**: 時刻の左右に [−15][+15]。時刻を押すとホイール（5 分刻み）。日付は出さず、就寝は「起床より前で最も近いその時刻」と解釈して自動で前日にする（0007 の「予定の開始 ±12h で最も近い日」と同じ考え）。カードの下に「8時間10分（予定 8時間 +10分）」をその場で更新
  - 理由: トレーニングの入力シート（± 小刻み・大刻み）と休憩バーの [−15][+15] と同じ手つき。片手・寝起きでも押せる
- エッジケース: 起床 7:00 で就寝を 6:50 に下げすぎた → 「10 分」の睡眠になる。2 時間未満なら時間の文字を注意色にするだけで止めない（昼寝はあり得る）。24 時間以上は入らない（DB で止める）

### S5 主観スコア（目覚め）
- **現状**: 実績欄のスコア「なし／1〜5」の選択（任意）
- **案（推奨）**: 記録した後のカードに「目覚め ① ② ③ ④ ⑤」の 1 行。押せばその場で保存、押さなくても完了。シートでも同じ行で直せる
  - 顔アイコンにするか数字にするかは見た目の好み（推測: 数字の方がグラフと一致して読みやすい）
- 不採用: スコアを必須にする（毎朝 1 タップ増える）／記録の前に聞く（保存の前に 1 段増える）

### S6 直す・消す（本人検討中の論点への案）
- **現状（0007 実装）**: 予定の編集画面の実績欄で時刻を直して保存・「記録を消す」（確認あり）
- **案（推奨）**: 記録そのものを直接いじる
  - 直す: 一覧の行（または今朝のカード）を押す → 下から記録シート（今朝のカードと同じ並び＋種類＋「記録を消す」）→ 保存
  - 消す: 一覧の行の左スワイプ（確認なし）／シートの「記録を消す」（確認あり）。予定外の実績（段階 2）と同じ作法
  - 消した後の今朝のカードは「未入力」に戻る（＝再入力がすぐできる）
- 差分: 予定の編集画面を開かずに直せる。「消したいのか、直したいのか」が 1 つのシートに集まる
- 取り消し（元に戻す）を足すかは本人の好み。足すなら画面下に 5 秒の「元に戻す」（推測: iOS 標準アプリで多い形。写真・メールなど）

### S7 記録し忘れ
- **案（推奨）**: 一覧の直近 7 朝は、記録が無い朝も「10/1(木) の朝 未入力 ［記録］」の行で出す。［記録］で予定の時刻で埋まったシートが開く。8 日より前は出さない（一覧が未入力で埋まらないように）。最初の記録より前の朝も出さない
- 「すべての記録 ›」で過去の全件（記録がある朝だけ）

### S8 予定タブの睡眠の行（本人決定「表示するだけ」の範囲で）
- **現状（0007 実装）**: 行の 3 行目に「未入力」／「実績 0:30–7:00（6時間30分）」。行を押すと予定の編集画面＋その下の睡眠の実績欄（入力できる）
- **案（推奨）**:
  - 行の表示は今のまま（3 行目に「実績 23:40–7:10（7時間30分）」／「未入力」、今夜の回は予定の就寝時刻を過ぎるまで何も出さない）。値は睡眠の表から「起床日 = 回の日 +1 の夜の睡眠」を表示時に引く（ジムの C4 と同じ「表示時に判定」）
  - 行を押す: 今までどおり予定の編集画面。その下の実績欄は**読むだけ**で「実績 23:40–7:10 · 目覚め 4」と「睡眠タブで直す ›」のリンク。リンクは睡眠タブに切り替えて、その朝の記録シートを開く（未入力なら予定の時刻で埋めたシート）
  - 差分: 実績欄の入力部品（`SleepActualSection` の入力）がなくなり、表示＋リンクになる
- 不採用: リンクも出さない（「未入力」を見て直したいときに、タブを探して日付をたどる手間が増える）／予定タブからも入力できる（本人が 10/1 に不採用にした「両方」）
- エッジケース: 予定の睡眠を 25:00 開始（翌 1:00）に変えた日。回の日は D のまま、起床日は D+1 なので結びは崩れない。予定の睡眠が 1 日に 2 つ（昼寝を予定に入れた）ときは、夜の睡眠は種類「睡眠」の最も遅い回、昼寝は表示時に時刻の重なりで結ぶ（推測で置いた規則。データ担当と詰める）

### S9 推移に出す指標
- 1 画面目（固定の 1 行。トレーニングの「🔥 n日 ◔ 今週 2/4」と同じ位置・高さ）:「🔥 12日 · 今週 平均 6時間52分（予定 −1時間08分）· 記録 4/5」
- 推移画面（右上 📊 で push。トレーニングの分析と同じ入口）:
  1. **範囲バー**: 夜ごとに就寝〜起床の棒、背景に予定の帯（23:00–7:00）。週／月／6 か月。ヘルスケアの週表示と同じ形
  2. **睡眠時間**: 夜ごとの棒と 7 日平均の線
  3. **就寝時刻**: 平均とばらつき（±分）。「規則正しさ」はこれで見る（Oura の規則性の簡易版）
  4. **予定との差の累計**: 直近 14 日で「予定より −5時間20分」（Rise の睡眠負債を予定基準で）
  5. **目覚めスコア**: 平均と夜ごとの点
  6. 昼寝: 週の合計
- 次の段（今回はやらない）: トレーニングとの重ね（前夜の睡眠時間 × その日のボリューム）。`domain-model.md` の「結合分析（睡眠スコア × 挙上重量）」に当たる。データは揃う

### S10 継続の仕組み
- **現状**: 継続の仕組みはトレーニングだけ（週 N 回の連続・リング・ヒートマップ・ウィジェット）
- **案（推奨）**: 睡眠にも 1 行の連続を出す。数えるのは「**記録した朝が続いた日数**」。未入力の朝を後から埋めれば連続が戻る（記録し忘れを責めない）
  - 理由: 睡眠タブが続く条件は、まず「毎朝入れる」こと。何時間寝たかで切れる連続は、寝不足の朝に開きたくなくなる（推測）
- 他の候補（本人に聞く）: 「予定の就寝 ±30 分に寝た夜」の連続／週に N 夜「予定の時間以上寝た」をトレーニングと同じ週基準で
- 不採用: 何も出さない（トレーニングと並べたときに睡眠だけ「続いている」が見えない）

### S11 ウィジェット
- 今回は作らない（実機での毎朝の使われ方を見てから）
- 次の段の案: ホーム小「昨夜 7時間30分 · 今週平均 6時間52分」。未入力の朝は「今朝の睡眠 ［記録］」のボタン（iOS 17 のインタラクティブ・ウィジェット＝App Intent で、予定の就寝＋今の時刻で保存。アプリを開かずに 1 タップ）。既存の StreakWidget と同じ拡張に同居

### S12 ヘルスケア
- 今回は取り込まない（段階 2 の C5 で「ヘルスケアで記録しているか未確認・後から足せる」と決まっている）
- 要件だけ: 後から取り込んだ記録と手入力が二重にならないように、記録に「どこから来たか（手入力／ヘルスケア）」と取り込み元の識別子を持てる形にしておく（列を今足すか、足すときに migration するかはデータ担当）

### S13 タブ
- 「予定・トレーニング・睡眠」。並びは予定タブの右（予定 → 毎日の記録 2 つ）
- 睡眠タブの 1 画面目は日付の切り替え（週帯）を**持たない**: 1 朝 1 件なので、トレーニングの週帯より「直近 7 朝の一覧」の方が短く、全部見える。週帯にするとタップで日を移るたびに 1 件しか見えない

## 4. データの要件（UX から。表の形はデータ担当が決める）

UX から必要なこと:
1. 記録は就寝・起床の時刻（timestamptz）を持つ。終了 > 開始、24 時間未満
2. 「どの朝か」（起床の JST 日）で引ける・一意にできる。夜の睡眠は 1 朝 1 件（2 件目を保存しようとしたら「この朝の記録を上書きしますか」— UI で先に止め、DB は最後の砦）
3. 種類（夜の睡眠／昼寝）
4. 目覚めスコア 1〜5（任意）
5. 予定の側とは結ばない（表示時に判定）。予定を消しても・変えても記録は変わらない
6. 後からヘルスケアを足せる（取り込み元・その識別子）
7. 予定タブの 1 回の読み込みで、D-1・D・D+1 の起床日の記録が取れる

叩き台（データ担当の比較用）:
```sql
CREATE TABLE sleep_record (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  kind        TEXT NOT NULL DEFAULT 'main' CHECK (kind IN ('main','nap')),
  bed_at      TIMESTAMPTZ NOT NULL,
  wake_at     TIMESTAMPTZ NOT NULL,
  wake_date   DATE NOT NULL,             -- 起床の JST 日。RPC が入れる（どの朝か）
  score       SMALLINT CHECK (score BETWEEN 1 AND 5),
  source      TEXT NOT NULL DEFAULT 'manual' CHECK (source IN ('manual','healthkit')),
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  CHECK (wake_at > bed_at AND wake_at - bed_at < INTERVAL '24 hours')
);
CREATE UNIQUE INDEX sleep_record_main_per_morning ON sleep_record (wake_date) WHERE kind = 'main';
CREATE INDEX sleep_record_wake_date ON sleep_record (wake_date);
```
- 0007 からは睡眠の分岐（`checkin_set` の `p_sleep_score`・`sleep_score_range`・睡眠の回の扱い）を抜く方向。`sleep_actual_input` は使わなくなる（件数の確認と削除の要否はデータ担当）
- 昼寝の判定境界・`wake_date` を列で持つか計算かもデータ担当

## 5. 既存との一貫性

| 既存 | 睡眠タブで揃えるもの |
|---|---|
| トレーニング: 前回値で埋めて ✓ だけ | 今朝のカードは予定と今の時刻で埋めて［記録する］だけ |
| トレーニング: 入力シートの ±、休憩バーの [−15][+15] | 就寝・起床の [−15][+15] |
| トレーニング: 右上 📊 で分析へ push | 右上 📊 で推移へ push |
| 継続: 週帯の上の 1 行「🔥 n日 ◔ 今週 2/4」 | 同じ位置・高さの 1 行「🔥 n日 · 平均 · 記録 4/5」（部品 `StreakViews` を使い回す想定） |
| 予定外の実績: 左スワイプで削除（確認なし）、編集画面の削除（確認あり） | 同じ |
| ジム C4: 表示時に判定・実績の行は書かない | 予定タブの睡眠の行は睡眠の表を表示時に引く |
| 開始ボタン廃止（儀式なし） | 寝る前の操作なし・朝の強制シートなし |

崩れる所（正直に）: トレーニングは週帯で日を移るが、睡眠タブは「直近 7 朝の一覧」で週帯を持たない（S13）。タブ間で日付の移り方が違う。

1. 連続（🔥）で数えるもの: 記録した朝（推奨）／予定の就寝 ±30 分の夜／週 N 夜の目標

## 7. 守護派に先に言っておくこと（反論の予告）
- 「タブを増やすと散らかる」→ 朝の入力は 2 タップで、0007 の予定タブ経由（最短 4 タップ・予定の編集画面を経由）より短い。睡眠だけの例外（丸を出さない・今夜の回を隠す・前日の回を開く）が予定タブの入力側から消える
