# 別案: 睡眠を別タブに移さない（予定タブの中で完結させる）

作成: 2026-10-02 / 担当: 別案（単独。他の担当のファイルは読まずに作成）/ 状態: 統合の比較対象

本人の決定「睡眠タブを足す」（10/1）だけを外して考えた案。それ以外の本人決定（就寝・起床の時刻で入力する、睡眠の予定 23:00〜8h は予定タブに残る、スマホ＋選択式、記録の前後に儀式を挟まない）は守る。

## 1. 「微妙さ」の中身（推測を含む）

本人は何が微妙かを言っていない。以下は**今の実装（未 commit の段階 2）を読んで AI が推測したもの**。事実は「今の実装がこうなっている」まで。

| # | 今の実装の事実 | 推測される微妙さ |
|---|---|---|
| a | 睡眠は actual_task に入っているが、丸なし・スキップなし・今夜の回は就寝の予定時刻まで実績欄を隠す・朝の行は前日の回・スコアは睡眠だけ、という睡眠だけの例外が `CheckInPlanner` に 4 か所ある（`showsCircle`・`acceptsActual`・`actualLine`・`circleStyle`） | 「予定の実績」の枠に睡眠を押し込んでいる感じ。チェックイン（やった／やらない）と測る記録（何時に寝た）が混ざっている |
| b | 朝に昨夜の睡眠を入れるには、一覧の「前日から継続」の行を押す → **今夜の睡眠の予定の編集画面**が開き、その下に「実績（9/29(火) の回）」が出る | 開いた画面の主役（今夜の予定）と、やりたいこと（昨夜の記録）がずれている |
| c | 睡眠の記録は「予定の回」に結びつく。予定が無い夜（除外日）や昼寝は「予定外の実績」になり、睡眠のデータが 2 種類に分かれる | 睡眠だけを並べて見ることができない |
| d | 睡眠の記録を一覧で見る場所・推移を見る場所がない。直す・消すは予定の編集画面の奥 | 記録した後に見返す楽しさがない（memory `feedback_motivation_ui`「入力フォームだけでは続かない」） |

**この案の見立て**: a〜c は**データの持ち方と入口の画面**の問題で、タブの数とは独立に解ける。d は「推移を見る場所」が要るという問題で、タブでなくても置ける。したがって「専用の表に分ける」と「タブを足す」は**別々に決められる 2 つの決定**として扱う。

## 2. 案の全体像（推奨形）

1. **データ**: 睡眠は actual_task から外し、専用の表 `sleep_record`（就寝・起床・スコア・昼寝か）に持つ。予定とは FK でつながず、ジム（C4）と同じく**表示時に判定**する
2. **どの夜に属するか**: **起床した日（JST）**。「10/2 の睡眠」= 10/2 の朝に起きた睡眠。一覧では、その日に**終わる**睡眠の予定の行（多くは「前日から継続」の最上段の行）に出す
3. **入口**: 予定タブの一覧で、睡眠の行の左（他の行の丸の位置）に**月のボタン**。押すと睡眠の記録シート（半分の高さ）。行そのものを押したときは今までどおり予定の編集（実績欄は出さない）。予定の無い日・昼寝は右上 ＋ の「睡眠を記録」
4. **推移・一覧**: 予定タブの左上に「睡眠」ボタン → 睡眠の画面（直近の推移グラフ＋記録の一覧。直す・消すもここ）を push で開く
5. **タブは「予定」「トレーニング」の 2 つのまま**

## 3. データの持ち方

### 3-1. 比較した持ち方
| 案 | 中身 | 判定 |
|---|---|---|
| A. actual_task に残す（今の実装） | 例外 4 か所が残る。昼寝・予定の無い夜は予定外の実績になり、睡眠の一覧を作るには種類で絞る必要 | 不採用。微妙さ a・c が残る |
| B. actual_task に残し、入口だけ専用シートにする | 例外は減るが「睡眠の回 = 予定の回」の結びつきは残る（今夜の回の扱い・前日の回の解釈） | 不採用。b は解けるが a・c が残る |
| **C. 専用の表 `sleep_record`（推奨）** | 予定とつながない独立の記録。トレーニング（`workout_session` は actual_task に従属しない）と同じ考え方。予定側は「その日に終わる睡眠の行に、その日の睡眠の記録を出す」だけ | **採用** |

### 3-2. DDL（案。migration は 0007 を書き換える。下の 3-4）
```sql
CREATE TABLE sleep_record (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  bed_at      TIMESTAMPTZ NOT NULL,                -- 就寝
  wake_at     TIMESTAMPTZ NOT NULL,                -- 起床
  wake_date   DATE NOT NULL,                       -- 起床の JST 日 = どの日の睡眠か・一覧に出る日
  is_nap      BOOLEAN NOT NULL DEFAULT false,      -- 昼寝 (1 日に何回でも)
  score       SMALLINT CHECK (score BETWEEN 1 AND 5),  -- 主観スコア (任意)
  created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT sleep_record_range_chk CHECK (wake_at > bed_at AND wake_at - bed_at <= interval '20 hours'),
  CONSTRAINT sleep_record_wake_date_chk CHECK (wake_date = (wake_at AT TIME ZONE 'Asia/Tokyo')::date),
  -- 睡眠どうしは重ならない (2 か所の入口から同じ夜を 2 回入れたときの最後の砦)
  CONSTRAINT sleep_record_no_overlap EXCLUDE USING gist (tstzrange(bed_at, wake_at) WITH &&)
);
-- 夜の睡眠 (昼寝でないもの) は 1 日 1 件
CREATE UNIQUE INDEX sleep_record_main_per_day ON sleep_record (wake_date) WHERE NOT is_nap;
CREATE INDEX sleep_record_wake_date_idx ON sleep_record (wake_date);
```
- `wake_date` は生成列（`GENERATED ALWAYS AS (...) STORED`）にできれば CHECK より良い。`AT TIME ZONE` が生成列で使えるかは**未検証**（使い捨て Postgres で確かめてから決める）
- `EXCLUDE ... tstzrange` は範囲型の gist で足り、`btree_gist` は要らない見込み（**未検証**）
- 書き込みは段階 1・2 と同じく RPC: `sleep_save(p_id, p_bed, p_wake, p_is_nap, p_score)`（新規／書き換え。起床 > JST の今は拒否）、`sleep_delete(p_id)`
- 将来の HealthKit 取り込み: `healthkit_sample_uuid TEXT UNIQUE` を足すだけ。domain-model の予定（endDate ＋ 18:00 境界）とは「起床の日で数える」点で同じ向き（18:00 境界は昼寝の扱いで差が出る。取り込むときに決める）

### 3-3. 「どの夜か」を起床日にする理由
- 今の実装は「就寝の予定の日（前日）の回」で持っているため、0:30 に寝た日・朝の行が前日の回になる、などの解釈が要った（実績時刻の ±12h 規則・前日の回の見出し）
- 起床日なら、**起床の時刻が決まれば日が決まる**。就寝は「起床より前で、その時刻になる最も近い時刻」で一意（23:40 → 前日、0:30 → 当日、13:10 → 当日の昼寝）。±12h の推測が要らない
- 人が言う「今朝の睡眠」「10/2 は 6 時間しか寝てない」とも一致する
- トレーニングとの突き合わせ（前夜の睡眠 × その日の挙上）は `sleep_record.wake_date = workout_training_day.day` の 1 本で書ける

### 3-4. 0007・旧 `sleep_actual_input` の扱い
0007 は本番未適用・未 commit なので、書き換えるのが最も安い。
- 0007 から睡眠の部分を外す: `checkin_set` の `p_sleep_score` 引数、`sleep_score_range`、スコアの upsert／削除
- `checkin_set`・`actual_save` で**種類が睡眠なら拒否**（睡眠が actual_task に入る経路を DB で塞ぐ。最後の砦）
- `sleep_actual_input` を DROP（本番の actual_task は 0 件なので移すデータは無い。0007 か、後の 0008 の旧列削除と一緒に）
- `sleep_record` の作成は 0007 に入れる（または 0008 として分ける。どちらでも本番は空から始まる）

### 3-5. 予定側の表示の規則（表示時判定。ジムの C4 と同じ型）
- 見ている日 D の一覧で、種類が睡眠（`sub_input_kind = sleep`）の行のうち **終了の JST 日が D の行**に、`wake_date = D` かつ昼寝でない記録を付ける
  - 23:00〜7:00 の予定 → D の一覧の最上段（前日から継続）の行
  - 1:00〜9:00 のように 0 時を過ぎてから始まる予定 → D の普通の行。同じ規則で付く
  - 今夜の行（終了が D+1）には何も付けない。今夜の記録は翌日の一覧に出る → **「今夜の回は就寝時刻まで隠す」例外が要らなくなる**
- その日に終わる睡眠の行が無い日（除外日など）や昼寝の記録は、一覧に**睡眠の行として単独で**時刻順に並ぶ（見た目は 4 章）
- 睡眠の行が 2 本その日に終わる（予定を重ねた）場合は、開始が早いほうに付ける（AI 既定。起きにくい）
- 取得: 今の 8 本の読み込みに `sleep_record WHERE wake_date = D` を 1 本足す（昼寝・単独の行もこれで足りる）

記録した後:
```
 (☾●) 睡眠                    〜7:00   ← 月が塗りに
      睡眠 · 前日から
      23:40–7:10（7時間30分）★4
```
予定の無い日・昼寝（単独の行。押すと記録シート）:
```

      睡眠 · 30分
```
- 月のボタン = 「この行の睡眠を記録する／直す」。行の本体を押す = 今までどおり予定の編集（実績欄は出さない）
- 丸と同じ位置・同じ大きさにして、並びと「左を押すと記録」の約束を揃える。チェックの丸とは形を変え、1 タップで記録が完了しないことを見た目で区別する
- 月を出す日: 過去日・今日。明日以降は出さない（丸と同じ）
- スワイプ: 睡眠の行のスキップは出さない（今のまま）。単独の睡眠の行は左スワイプで削除（予定外の実績と同じ）

### 4-2. 睡眠の記録シート（`.medium` の高さ。月 or ＋「睡眠を記録」から）
```
 キャンセル     10/2(金) の睡眠      保存
 ─────────────────────────────────
 就寝      [ 23 : 40 ]   10/1(木)       ← 時・分のホイール（5 分刻み）
 起床      [  7 : 10 ]
           7時間30分
 ─────────────────────────────────
 スコア    [なし][1][2][3][4][5]        ← 任意。既定「なし」
 昼寝      ( off )                      ← 月から開いたときは出さない
 ─────────────────────────────────
           記録を消す                    ← 既存の記録を開いたときだけ（確認あり）
```
- 既定の時刻（AI 既定）:
  - 就寝 = その行の予定の開始（例 23:00）
  - 起床 = 今が予定の起床の ±3 時間以内なら**今**（5 分単位に切り捨て）、それ以外は予定の終了。朝起きてすぐ開くと起床が合っている
  - ＋ から開いたとき: その日に夜の睡眠が未入力なら夜の睡眠として予定の時刻、入力済みなら昼寝 on・13:00〜13:30
- 日付の解釈: 起床の日はシートの日（見ている日 D）で固定。就寝は「起床より前で最も近いその時刻」。日付が前日になったときだけ右に日付を出す（「10/1(木)」）。±12h の推測はしない
- 保存できない場合（重なり・20 時間超・未来の起床）は footer に赤で理由（「10/2 13:10–13:40 の昼寝と重なっています」など）

- 置き場の考え方: 「予定タブの中の、睡眠だけを並べた画面」。トレーニングの「分析」（`WorkoutView` の toolbar から push）と同じ型

### 4-4. 朝起きてすぐの流れ（タップ数）
| 場面 | 流れ | タップ |
|---|---|---|
| 就寝が予定どおり・起きてすぐ | アプリを開く（予定タブ・今日）→ 最上段の月 → 保存 | **2**（起床は「今」が入っている） |
| 就寝がずれた | 月 → 就寝のホイールを回す → 保存 | 2 ＋ ホイール |
| スコアも付ける | 月 → スコアの数字 → 保存 | 3 |

### 4-5. 直す・消す（本人検討中の論点への答え）
- **直す**: 月（塗り）・単独の行・睡眠の画面の行、どれを押しても同じシート。時刻・スコアを変えて保存
- **消す**: シートの「記録を消す」（確認あり）／睡眠の画面・単独の行の左スワイプ（確認なし）
- **月をもう一度押しても消えない**（丸と違う）。時刻を入れた記録を 1 タップで失わないため
- 消した後は「未入力」に戻る。予定の側には何も残らない（実績の行が無いので後始末が要らない）

## 6. 別タブ案との比較（正直に）

### この案が良い点
- **朝の入口が近い**: アプリを開いた最初の画面の最上段に月がある。タブを切り替えない分 1 タップ少ない見込み
- **1 日の流れの中に睡眠が見える**: 予定と実績が同じ行に並ぶ。spec の原則 1（1 日は全結合。起床 → 就寝の影響）と合う
- **入口が 1 種類の画面に集まる**: 記録・直す・消すが同じシート。タブ側と予定側の 2 か所の記録画面を揃える手間がない
- **後戻りが安い**: 睡眠の画面は push で開く 1 つの View なので、後からタブに載せ替えるのは入れ物を変えるだけ（データ・シートはそのまま）。逆（タブ → push）も同じ程度

### この案が弱い点（別タブ案のほうが良い点）
- **本人の直感に正面から応えていない**: 本人は「トレーニングと同様に分けた方がいいかも」と言い、10/1 に「専用のタブ」を選んでいる。この案はトレーニング（タブ）と睡眠（予定タブの中）の扱いが非対称になる
- **推移が一段深い**: 予定タブ → 左上「睡眠」→ 画面。毎日推移を眺めたいなら、タブバーから 1 タップの別タブが勝つ
- **予定タブの責務が増える**: 予定・実績のチェックイン・睡眠の記録・睡眠の推移の入口が 1 タブに集まる。toolbar の左右・＋ メニューの項目が増える
- **月と丸の 2 種類の左のボタン**: 押したときの動き（丸 = その場で完了、月 = シートが開く）が違うことを覚える必要がある
- **予定の無い日の入口が見つけにくい**: 睡眠の予定を消した日・旅行などは ＋ メニューか睡眠の画面からしか入れない（別タブなら常に同じ場所）
- **将来の睡眠の機能（HealthKit 取り込み・睡眠の目標・連続）の置き場**: 増えるほど別タブのほうが収まりが良い

### どちらでも同じ点
- 専用の表・起床日で数える・表示時判定・0007 の書き換え・直す／消すの操作は、タブの有無と独立に決められる

## 7. エッジケース

| 場面 | この案での扱い |
|---|---|
| 0:30 に寝た | 就寝 0:30 < 起床 7:00 なので同じ日。起床日 = その日の一覧の最上段の行に付く |
| 徹夜（寝ていない） | 記録しない。一覧は「未入力」のまま。「寝なかった」を残す状態は作らない（必要になったら足す） |
| 二度寝・中途覚醒 | 最初の就寝〜最後の起床を 1 件。中途覚醒は持たない |
| 夜の睡眠を 2 回入れた（月と ＋ の両方から） | 一意索引で 2 件目は保存できず、シートに「10/2 の睡眠はもうあります」。＋ から開いたときは入力済みなら昼寝 on が既定なのでほぼ起きない |
| 昼寝が夜の睡眠と重なる | 重なり禁止の制約で止まり、シートに理由を出す |
| 昼過ぎまで寝た（7:00 予定 → 13:00 起床） | 夜の睡眠として記録できる（昼寝かは本人が選ぶ。月から開けば夜の睡眠） |
| 睡眠の予定を 1:00〜9:00 に変えた | 「終了の日が D の睡眠の行」の規則なので、前日から継続の行でなくても付く |
| 予定を消した日の記録 | 記録は残り、単独の睡眠の行として出る（予定とつながっていないので後始末なし） |
| 未来の日 | 月を出さない。RPC も起床 > 今を拒否 |
| 過去日 | 月で記録・修正できる（実績は過去日も入力可という段階 2 の方針どおり） |

## 8. 本人に聞く論点（統合で別タブ案と並べるとき用）

決裁チェックリストの形。推奨を先頭に置く。

**Q-alt-1. 睡眠を別タブにするか、予定タブの中に置くか**
1. 要点: 現状（予定の編集画面の奥の実績欄）→ 別タブ案: 睡眠タブで記録・一覧・推移 ／ この案: 予定の一覧の睡眠の行の月から記録、推移は予定タブ左上「睡眠」から開く画面
2. エッジケース: 予定を消した日の睡眠は、この案では ＋ か睡眠の画面からしか入れない
3. 可逆性: 戻せる。睡眠の画面を tab と push のどちらに載せるかの差で、データとシートは共通
4. 記録先: `day-cycle-walkthrough.md` の段階 2 の保留、`sleep-design/synthesis.md`
5. 他の選択肢: 両方（タブ＋予定の行の月）＝入口 2 つでも記録シートが 1 つなら作る量は小さい。10/1 に「両方」を不採用にした理由は「入口 2 つで作る量が増える」だったので、シートを共通にする前提なら再検討の余地がある

**Q-alt-2. どの日の睡眠として数えるか**（タブの有無に関係なく必要）
- 推奨: 起床の日（10/2 の朝に起きた睡眠 = 10/2 の睡眠）。不採用: 就寝の予定の日（今の実装。0:30 就寝などで解釈が要る）

**Q-alt-3. 月をもう一度押したとき**
- 推奨: 何もしない（シートが開くだけ）。消すのはシートの「記録を消す」。不採用: 丸と同じく 1 タップで消す（時刻を入れた記録を誤って失う）
