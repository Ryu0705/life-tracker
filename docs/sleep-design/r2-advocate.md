作成: 2026-10-02 / 立場: 推進派 / 読んだもの: `r1-guardian.md`、`r1-data.md`（`alt-no-tab.md` は冒頭だけ。別案も「起床した日」で数えていることだけ参照）/ コード・DB・git には触れていない

判定の記号: **採る**（自案を取り下げて相手に合わせる）／**採らない**（自案を維持）／**条件付き**

## 1. 最大の対立点: 「どの夜か」と「予定の行への付け方」

### 1-1. 三者の案を分解する
対立して見えたのは、実は 3 つの別々の問いが 1 つにまとまっていたからだった。

| 問い | 推進派 R1 | 守護派 | データ担当 | R2 の判定 |
|---|---|---|---|---|
| (i) DB に何を持つか | 起床の日 `wake_date` を列に持つ | 生の時刻だけ。夜は導出 | 生の時刻だけ。夜は表示時に計算 | **採る**（列を持たない） |
| (ii) 夜をまとめる鍵（pure 関数） | 起床の日 | (a) 起床の日 か (b) 就寝 −12h、本人に聞く | 就寝 −12h の JST 日（N1）＋就寝 18:00〜翌 6:00 を夜の睡眠とする | **採る**（N1 を鍵にする） |
| (iii) 画面での呼び方 | 「10/2(金) の朝」 | 寝た夜「9/30 の夜」を推奨 | 「9/30 の夜」を推奨。文言だけの違いにもできる | **採らない**（「朝」の呼び方は残す。ただし (ii) の鍵からの表示変換にする） |
| (iv) 予定の行への付け方 | 起床の日 = 回の日 +1 で結ぶ | 時刻の重なり。重なりが最大の回 1 つだけ | 時刻の重なり。重なりが長い行へ | **採る**（時刻の重なり） |
| (v) 重複の防ぎ方 | 夜の睡眠は 1 朝 1 件の一意制約 | 時間の重なり禁止（RPC＋可能なら EXCLUDE） | EXCLUDE（拡張なしで作れたことを確かめ済み） | **採る**（重なり禁止。「1 朝 1 件」は表示の規則に移す） |

### 1-2. 譲る理由（事実で負けている所）
- (iv) 起床の日で結ぶと、守護派 §2-2 の場合で外れる。「これ以降」で睡眠を 1:00〜9:00 に変えた世代では、D の回は D の 1:00 に始まる。0:50 に寝た記録は起床の日が D なので「回の日 +1」の規則では D−1 の回に付いてしまう。時刻の重なりなら世代に依らず付く。反論の余地がない
- (v) 1 朝 1 件の一意制約は、分割した夜（23:30–3:00 と 3:30–7:00）を禁じる。そのうえ、規則を変えると制約まで作り直すことになる。重なり禁止なら、どちらの問題も起きない
- (i) 時刻を直したのに `wake_date` を直し忘れる、という二重管理を自分の案で作っていた（規約 C-6・INV-5）。取り下げる
- (ii) データ担当 §2-1 の表で、起床の日（N2）は分割した夜を 2 日に割ると確かめられている。N1 はこれを 1 夜にまとめる。鍵としては N1 の方が強い

### 1-3. 「朝」の呼び方は残す（ii と iii は両立する）
- N1 で夜の睡眠と分類された記録（就寝が 18:00〜翌 6:00）は、ほぼ必ず「鍵の日 +1」の朝に起きる。そこで **呼び方 =「(N1 の日 +1) の朝」** という表示の変換を 1 つ足せば、鍵は N1、見出しは「10/2(金) の朝」のまま保てる。DB にも鍵にも影響しない
- 「朝」を残す理由（UX）
  1. 入れるのは朝。「今朝の睡眠」を入れる画面で「昨日（10/1）の夜」と見出しを出すと、毎朝一瞬「どの日？」と考えさせる
  2. 昼寝と同じ日にまとまる。一覧を暦日 D でまとめると、「D の朝に起きた夜の睡眠」と「D に始まった昼寝」が同じ見出しの下に並ぶ。「夜」の呼び方だと、10/1 の 14:00 の昼寝は「9/30 の夜」と「10/1 の夜」のどちらの下にも素直に入らない
  3. Apple ヘルスケアも起きた日の側で数える（R1 §1。事実としての確度は R1 と同じで、実物は開いていない）。別案（alt-no-tab）も起床の日を採っている
- 守護派の「寝た夜」の理由（予定タブの 23:00 の行と呼び方が揃う）は認める。ただし予定タブには見出しが無く、行が並ぶだけ。呼び方がぶつかる画面は無い
- 結論: **呼び方は本人に聞く論点として残し、推奨は「朝」**。鍵（N1）とは独立なので、どちらに決めても DB・pure 関数の鍵は変わらない（変わるのは表示の 1 関数だけ）

### 1-4. 「1 朝 1 件」は表示の規則として残す
- DB は重なり禁止だけにする。画面では、同じ鍵（N1）の夜の睡眠を 1 件にまとめて出す（就寝 = 最初、起床 = 最後、睡眠時間 = 合計。データ担当 §2-4 の規則をそのまま使う）
- 今朝のカードは「その朝のまとめ」を見る。記録が 1 件でもあれば「記録済み」の表示にする
- 保存が重なりで拒否されたとき（23P01）は、文言「この時間には記録があります」を出し、その記録のシートを開く（守護派 §2-5 の文言に合わせる）。R1 の「この朝の記録を上書きしますか」は取り下げる

### 1-5. 昼寝: 種類の列・自動判定・本人が選ぶ
| 案 | 中身 | 判定 |
|---|---|---|
| 推進派 R1 | 種類の列。時刻から自動で選び、シートで変えられる | 取り下げる |
| 守護派 | 自動判定しない。本人が選ぶ（既定は本睡眠）。そもそも記録するかを本人に聞く | **条件付きで一部採る**（記録するかは本人に聞く） |
| データ担当 P1 | 列なし。就寝の時刻で表示時に分ける | **採る** |
- 理由: P1 なら記録シートに切り替えが 1 つも増えない（入力の手間が最小。推進派が最も重視する点）。分け間違えても、表示の定数を変えるだけで済む（データは変わらない）。守護派が挙げた誤判定の例（夜勤明け・徹夜明け）は本人の生活ではまれ（推測）。外れても推移の分類がずれるだけで、記録は失われない
- R1 で挙げたエッジ（18:00 に寝落ち → 23:00 に起きて 0:30 に寝直す）は、P1 では同じ鍵の夜の睡眠 2 件になり、1 夜に合算される。「夕方の寝落ちも夜の睡眠に数える」という結果で、害は小さい（推測）
- 昼寝を記録すること自体を今回の範囲にするかは本人に聞く（守護派 Q2・データ担当 Q1 と同じ）

R1 の各項目を、守護派の線に当てて自己採点した。○ = 今回の範囲に入れる／× = 今回は外す（次の段か本人の決定待ち）。

| R1 の項目 | 守護派の線 | 自己採点 | 理由 |

| 今朝のカード（埋まった状態で［記録する］） | 2 タップ＋直す分まで | ○ | ちょうど 2 タップ。推進派の中心なので譲らない |

### 🔥 連続を外す理由（自己採点 ×）
- トレーニングの継続の仕組みは「週 N 回トレーニング」という本人の基準があって決まった（continuity-design）。睡眠で何を数えるか（記録した朝／予定どおり寝た夜／週 N 夜）は、本人がまだ何も言っていない。推進派の R1 の推奨（記録した朝）も AI の推測にすぎない
- 連続の部品（`StreakViews`）を使い回せば作る量は小さい。だが、数え方が決まらないまま出すと後で数字の意味が変わり、それまでの連続が化ける
- → 今回は外す。代わりに 1 画面目の 1 行の「記録 4/5」で、入れ続けているかだけは見えるようにする。連続は、実機で毎朝使われ始めてから本人に「何を数えたいか」を聞く（統合の「次の段で聞く論点」に回す）

作る量の目安（守護派 §5: 表 1・RPC 2〜3・タブ 1・予定タブの表示関数 1）に対しては、表 1・書き込み 2〜3・タブ 1（今朝のカード＋7 朝の一覧＋すべての記録＋推移＋シート）・表示関数 1 になる。「すべての記録」の画面が 1 つ多いが、一覧の延長（同じ行の部品）なので線の内側と判断する。

## 4. 修正後の推奨案（R2 時点の推進派案）

### データ（データ担当 R1 に乗る）
- `sleep_record(id, start_at=就寝, end_at=起床, score 1〜5 任意, created_at)`。予定・category への参照なし。EXCLUDE で重なりを禁止し、24h 上限と end > start
- 鍵（どの夜か）は pure 関数 1 つ: 就寝が 18:00〜翌 6:00 なら夜の睡眠で、鍵 = 就寝 −12h の JST 日（N1）。それ以外は昼寝で、開始の JST 日
- 同じ鍵の夜の睡眠は表示で 1 件にまとめる

### 睡眠タブ
```
┌ 睡眠                                              [📊] ┐
│ 今週 平均 6時間52分 · 記録 4/5                          │ ← 連続は出さない
├───────────────────────────────────────────────────────┤
│ 10/2(金) の朝                                           │ ← 見出し = 鍵 +1 の朝（呼び方は本人に聞く）
│ 就寝   [−15]   23:00   [+15]                            │ ← 予定の就寝 → 直近の記録 → 23:00
│ 起床   [−15]    7:10   [+15]                            │ ← 開いた時刻（条件外は予定の起床 → 7:00）
│ 8時間10分                                               │ ← 予定との差は出さない
│                                   [ 記録する ]          │
├───────────────────────────────────────────────────────┤
│ 直近の朝                                                │
│ 10/1(木)  23:40–7:10  7時間30分  ④                      │
│ 9/30(水)  未入力                              [記録]    │
│ 9/29(火)  0:30–7:00   6時間30分  ③                      │
│           昼寝 13:10–13:40  30分                         │ ← 昼寝を記録すると決まった場合だけ
│ すべての記録 ›                                          │
└───────────────────────────────────────────────────────┘
```
- 記録後は今朝のカードが「23:00–7:10 · 8時間10分 ✓」と「目覚め ①〜⑤（任意）」に変わる
- 記録シート: 就寝・起床（[−15][+15]＋時刻を押すとホイール）・目覚め・「記録を消す」（既存の記録だけ・確認あり）。種類の切り替えは無い
- 重なりで拒否されたら「この時間には記録があります」を出し、その記録のシートを開く
- 推移（📊 で push）: 週／月／6 か月の範囲バー（予定の帯なし）と睡眠時間の棒（7 日平均の線）、平均の数字 1 行（睡眠時間・就寝時刻・目覚め）

### 予定タブ
- 睡眠の行: 結べた記録があるときだけ 3 行目に「実績 23:40–7:10（7時間30分）」を出す。「未入力」は出さない
- 結び方: 時刻の重なり（予定の本来の範囲と、記録の [就寝, 起床) が重なる。1 件の記録は重なりが最大の行 1 つにだけ付ける）
- 行を押す: 今日・未来は今までどおり予定の編集画面（睡眠の実績欄は出さない）。過去日は押せない（段階 1 に戻す）
- 丸を出さない・幅だけ取る（`.hidden`）・スワイプでスキップしない、は 9/30 のまま

### 今回は外すもの（次の段の候補）
🔥 連続・ウィジェット（記録ボタン付き）・予定との差の分析・就寝のばらつきの数字・昼寝の合計・元に戻す・予定タブから睡眠タブへのリンク・ヘルスケア

### 本人に聞く論点（推進派から。統合で決裁チェックリストに）
1. 見出しの呼び方:「10/2(金) の朝」（推奨）か「10/1(木) の夜」か。鍵と DB はどちらでも同じで、表示だけの違い
2. 昼寝を記録するか（する場合は時刻で自動に分け、切り替えの入力は無し）
3. 予定タブの過去日の睡眠の行を押せなくする（推奨）か
4. 直す・消すの形（保留中の論点）: シートで直す、左スワイプとシート内の「記録を消す」で消す（推奨）
5. （次の段）睡眠で連続を数えるなら何を数えるか
